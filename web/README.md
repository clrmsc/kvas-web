# Веб-интерфейс Кваса

Один статический бинарник, который отдаёт веб-интерфейс и управляет Квасом
через его CLI. Ни socat, ни shell-CGI, ни внешних библиотек: интерфейс вшит
внутрь исполняемого файла, зависимостей во время работы нет.

## Что заменено по сравнению с апстримом

| | Апстрим (`opt/bin/monitor`) | Здесь |
| --- | --- | --- |
| HTTP-сервер | socat + shell-обработчик на каждый запрос | net/http в одном процессе |
| Логика | CGI на shell (~1400 строк) | Go с валидацией входных данных |
| Пароль | md5 без соли | PBKDF2-SHA256 со случайной солью |
| Сессия | токен в query string, файл в `/tmp` | HttpOnly-cookie, `SameSite=Strict` |
| CSRF | нет | проверка `Origin` для изменяющих запросов |
| Инъекции | параметры подставлялись в командную строку | `exec` без шелла + проверка доменов и IP |
| Долгие операции | ожидание ответа целиком | прогресс потоком (server-sent events) |
| TLS | нет | опционально, ключи из `kvas.conf` |

## Сборка

```sh
make all      # бинарники под mipsle, mips, aarch64, armv7 в build/
make test     # тесты
make host     # бинарник для машины разработчика
```

`make all` нужно выполнить до сборки ipk: `Package/kvas/install` берёт
`web/build/kvasweb-<арх>` и кладёт его в `/opt/apps/kvas/bin/kvasweb`.

Соответствие архитектур: `mipsel` → `mipsle` (mt7621, KN-2710 и большинство
моделей на MIPS), `aarch64` → `aarch64`, `arm` → `armv7`.

## Локальный стенд

```sh
sh dev.sh
```

Поднимает интерфейс на <http://127.0.0.1:8099> с песочницей в
`/tmp/kvasweb-dev`: конфигурационные файлы Кваса и скрипт-заглушка вместо
настоящего CLI. Роутер не нужен. `sh dev-sandbox.sh` пересоздаёт песочницу.

## Запуск на роутере

Автоматически — при установке пакета и при загрузке (`/opt/etc/init.d/S99kvasweb`).
Вручную:

```sh
kvas web            # запустить
kvas web status     # проверить
kvas web off        # остановить
```

Настройки в `/opt/etc/kvas.conf`:

```
WEB_PORT=8085
WEB_TLS_CERT=
WEB_TLS_KEY=
```

Если указать сертификат и ключ, сервис поднимется по HTTPS и пометит
cookie флагом `Secure`.

## Первый вход

Пароля изначально нет: первый, кто откроет интерфейс, задаёт его сам.
Чтобы это окно не мог перехватить кто-то извне, первичная настройка
принимается только с адресов домашней сети (RFC 1918, loopback, link-local).
Задайте пароль сразу после установки.

Защита от подбора: после 5 неверных попыток вход блокируется на 5 минут.
Смена пароля завершает все сессии.

## Подписка и автоматический выбор сервера

Во вкладке «Подписка» задаётся ссылка провайдера
(`https://…/subscription/vless/…`). Раз в сутки в назначенное время все
серверы из неё проверяются:

1. измеряется задержка TCP-подключения до каждого (лучшая из трёх попыток);
2. у нескольких самых отзывчивых поднимается временный экземпляр xray на
   свободном порту, и через него качается тестовый файл — так измеряется
   реальная скорость именно через туннель, а не до сервера;
3. серверы сортируются: решает скорость, но при разнице до 15 % выигрывает
   меньшая задержка;
4. если включено «Переключаться автоматически», лучший сервер становится
   рабочим: генерируется конфигурация xray, проверяется через `xray -test`,
   подменяется `/opt/etc/xray/kvas.json` и перезапускается служба.

Прежняя конфигурация сохраняется рядом (`kvas.json.kvasweb-bak`). Если после
перезапуска SOCKS-порт туннеля не открылся, изменения откатываются
автоматически и в журнале остаётся причина.

Проверку можно запустить вручную кнопкой «Проверить сейчас» — она идёт в
фоне, и закрытая вкладка её не прерывает. Если на сегодня плановая проверка
ещё не выполнялась, она стартует сразу после включения расписания или после
перезагрузки роутера.

Ссылка на подписку хранится в `/opt/etc/kvas-web/subscription.json` с правами
`0600`, в интерфейсе показывается сокращённой и вырезается из сообщений об
ошибках: в ней токен доступа к вашим серверам.

Что настраивается: время суточной проверки, число серверов для замера
скорости (по умолчанию 5), автопереключение и сама проверка по расписанию.
Расход трафика — около 5 МБ на замер одного сервера.

## API

Все изменяющие запросы — `POST`/`DELETE` с телом в JSON и cookie-сессией.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/auth/state` | задан ли пароль, есть ли сессия |
| `POST /api/auth/setup` | задать первый пароль (только из локальной сети) |
| `POST /api/auth/login` | вход |
| `POST /api/auth/logout` | выход |
| `POST /api/auth/password` | смена пароля |
| `GET /api/status` | сводка: режим, туннели, счётчики |
| `GET /api/hosts` | список защищённых доменов |
| `POST /api/hosts` | добавить домен |
| `DELETE /api/hosts/{домен}` | удалить домен |
| `POST /api/hosts/import` | импорт списка, прогресс потоком |
| `GET /api/hosts/export` | выгрузка `kvas.list` |
| `GET /api/tags` | закваски и их состояние |
| `POST /api/tags/{имя}/enable` | включить закваску целиком |
| `POST /api/tags/{имя}/disable` | выключить закваску |
| `GET /api/routes` | правила маршрутизации по устройствам |
| `POST /api/routes` | добавить правило (`full`, `list`, `exclude`) |
| `DELETE /api/routes/{тип}/{ip}` | удалить правило |
| `GET /api/routes/devices` | устройства сети из DHCP и ARP |
| `GET /api/adblock` | состояние блокировки рекламы |
| `POST /api/adblock` | включить или выключить |
| `GET /api/adblock/blocked` | заблокированные сайты |
| `POST /api/adblock/blocked` | заблокировать сайт |
| `DELETE /api/adblock/blocked/{домен}` | разблокировать |
| `GET /api/subscription` | ссылка (сокращённая), расписание, результаты |
| `POST /api/subscription` | сохранить ссылку и настройки проверки |
| `GET /api/subscription/servers` | состав подписки без проверки |
| `POST /api/subscription/check` | запустить проверку, прогресс потоком |
| `POST /api/subscription/apply` | переключиться на выбранный сервер |
| `GET /api/vpn` | состояние туннелей и резервного канала |
| `POST /api/vpn/mode` | переключить на `vless` или `hysteria` |
| `POST /api/service/init` | пересобрать таблицы, прогресс потоком |
| `POST /api/service/update` | обновить списки, прогресс потоком |
| `POST /api/service/backup` | резервная копия настроек |
| `GET /api/logs` | хвост журнала веб-сервиса |

## Устройство

```
cmd/kvasweb        точка входа: флаги, журнал, HTTP-сервер
cmd/fakexray       заглушка xray для локального стенда (в пакет не входит)
internal/config    пути к файлам Кваса и настройки сервиса
internal/auth      пароль, сессии, защита от подбора
internal/kvas      запуск CLI, чтение kvas.conf и списков, проверка ввода
internal/keenetic  локальный RCI роутера (имена устройств из DHCP)
internal/subscription  загрузка подписки, разбор ссылок vless://, конфиг xray
internal/probe     замер задержки и скорости (свой клиент SOCKS5)
internal/autovpn   состояние подписки, суточное расписание, переключение
internal/httpapi   маршруты и обработчики
ui/dist            интерфейс: index.html, app.js, style.css (вшиваются)
```

Источник истины — сам Квас: сервис читает его файлы и вызывает его команды,
своего состояния (кроме пароля и сессий) не хранит.
